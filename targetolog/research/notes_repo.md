## 0. Коротко

1. Это не программа, а набор промптов для Claude Code. Ценность в правилах безопасности, шаблонах (бриф, отчёты, журнал действий) и в идее «бриф → план → подтверждение → создание на паузе → лог». Логика решений (Health Score и пороги) эвристическая, ничем не проверена и противоречит сама себе.
2. Подключение к Meta для нас устарело. В репо бессрочный Admin-токен System User лежит открытым текстом в файле и работает через самодельный форк MCP. Официальный коннектор безопаснее и богаче (бенчмарки, аномалии, журнал активности, A/B, Ad Library, справка Meta), но генерации картинок в нём нет.
3. В текущем виде репо не работает. Скиллы лежат не в `.claude/skills/`, внутренние пути `.claude/ads-agent/...` не совпадают со структурой, в доках три разных MCP-сервера, один файл обрезан, часть упомянутых папок не существует, а в docs/01 есть CLI-команды, которых, по нашим данным, в Claude Code нет.
4. Опасные места:
   - оптимизатор требует тратить 95–105% плана: добавляет бюджет «лучшему из плохих» и создаёт новые адсеты из «освободившихся» денег;
   - в сценарии `campaign-manager` сразу за созданием идёт шаг «Активация» с `resume_campaign`;
   - troubleshooting советует включить адсет, чтобы его отредактировать;
   - пороги рассчитаны на дешёвый рынок СНГ;
   - нет Special Ad Categories;
   - примеры текстов нарушают правила Meta (Ozempic, знаменитости, «−10 кг в месяц»).
5. Файла LICENSE нет. README заявляет MIT, но похоже, что это перепаковка чужого репо (dengineproblem, «AI-агентство Performante»). Поэтому текст не копируем: берём идеи и пишем своё.

## 1. Что это и как устроено

**Суть.** 12 скиллов, конфиг аккаунтов и брифов, база знаний. Все вызовы API идут через внешний MCP-сервер `meta-ads` (см. §2). Своих скриптов нет. Формулы (Health Score, Risk Score, подсчёт лидов) даны псевдокодом на Python, который модель должна «исполнять в уме».

**Цепочка загрузки инструкций**
1. `CLAUDE.md` в корне Claude Code загружает автоматически, если запущен в этой папке. В нём пять правил:
   - читать `config/ad_accounts.md` и бриф перед любой операцией;
   - показывать план и ждать подтверждения;
   - бюджеты, пауза/возобновление и создание всегда требуют подтверждения;
   - логировать в `history/YYYY-MM/YYYY-MM-DD.md`;
   - перед оптимизацией читать историю за 3 дня.

   Файл ссылается на `config/AGENT.md` и `config/knowledge/*`.
2. `config/AGENT.md` — «полная инструкция агента»: роль, маршрутизация по скиллам, список из 47 MCP-инструментов, алгоритм реестра креативов, формат лога, пример процесса. Автоматически не грузится, Claude читает его по ссылке.
3. `skills/<name>/SKILL.md` — 12 скиллов с YAML-фронтматтером (`name`, `description`). `skills/ads-agent` служит точкой входа (почти копия AGENT.md) и маршрутизирует к остальным.

**Как Claude Code подхватывает скиллы и почему здесь не подхватит.** Claude Code ищет скиллы в `.claude/skills/<name>/SKILL.md` проекта, в `~/.claude/skills/` или в плагинах. В контекст попадают `name` и `description`: модель вызывает скилл сама по описанию, либо пользователь пишет `/name`.
- В репо скиллы лежат в корневой `skills/`, поэтому `/ads-agent` из коробки не появится. Шага «перенести в .claude/skills» нет ни в README, ни в QUICKSTART.
- В 10 скиллах из 12 (кроме campaign-manager и targeting-expert) и в `config/knowledge/safety_rules.md` пути вида `.claude/ads-agent/config/...`, `.claude/ads-agent/knowledge/...`, `.claude/ads-agent/history/...`. В репо же `config/`, `config/knowledge/`, `history/`.
- Видимо, у автора исходно всё лежало в `.claude/`, а при перепаковке структуру поменяли и пути не поправили.

**Папки состояния**
- `history/` (в .gitignore, пустая, только `.gitkeep`) — журнал действий, один файл на день. Формат: таблица `# | Тип | Object ID | Object Name | Old | New | Причина | Статус` плюс контекст (целевой CPL, аккаунт, распределение HS, «история учтена»). Типы действий: `budget_increase/decrease`, `pause_ad/adset`, `resume_ad/adset`, `create_adset/campaign`, `update_targeting`. Журнал нужен правилам «анти-качелей» (§4).
- `reports/` (в .gitignore, пустая). README и QUICKSTART обещают здесь HTML-отчёты, но ни один скилл HTML не пишет: `ads-reporter` выводит markdown в чат.

**Конфиги**
- `config/ad_accounts.md` — блок на каждый аккаунт: Account ID (`act_…`), Page ID, Instagram ID, название, сайт, ссылка на бриф, статус (активен / приостановлен / архив), валюта, часовой пояс, тип конверсии, заметки. Там же описано, где искать ID.
- `config/briefs/_template.md` — шаблон брифа (§5).
- `config/creatives.md` — реестр креативов по `creative_tag`: описание, тип, файл, дата, статус, заметки, плюс таблица быстрого поиска.
- `config/naming_convention.md` — имя объявления `{creative_tag}_{описание}`.
- `config/knowledge/` — safety_rules, fb_best_practices, metrics_glossary, troubleshooting, geo_locations (§4).
- Упомянуты, но в репо отсутствуют:
  - `config/creatives/{account}/index.md` и README к нему (из AGENT.md);
  - `config/naming/{account}_naming.md` (создаёт его скилл naming-rules);
  - `~/meta-ads-mcp/CUSTOM_EXTENSIONS.md` (ссылка из ads-agent, «16 custom tools»).
- Файла `.claude/settings.json` с разрешениями нет. Правило «без подтверждения ничего не менять» держится только на тексте промпта, технически его ничто не обеспечивает.

## 2. Подключение к Meta в репозитории

**Сервер.** В `.mcp.json.example` описан stdio-сервер `meta-ads`: запуск `uv run --directory /ABSOLUTE/PATH/TO/meta-ads-mcp meta-ads-mcp`, в env `META_APP_ID`, `META_APP_SECRET`, `META_ACCESS_TOKEN` (System User Token). docs/00 добавляет `GEMINI_API_KEY` для генерации картинок.

**В документации три разных источника сервера, и они противоречат друг другу:**

| Документ | Откуда берётся сервер |
|---|---|
| QUICKSTART, фаза 4 | `github.com/pipeboard-co/meta-ads-mcp` (публичный; по README лицензия BSL 1.1) |
| docs/00, шаг 6 | `github.com/dengineproblem/meta-ads-mcp-extended` |
| docs/02 | `github.com/YOUR_USERNAME/meta-ads-mcp-extended` (заглушка) или удалённый Pipeboard `https://mcp.pipeboard.co/meta-ads-mcp` с заголовком `Authorization: Bearer pb_live_…` |

Скиллы вызывают инструменты расширенного форка (47 или 46 инструментов, «16 custom»): `pause_*`/`resume_*`, `upload_video`, `create_video_creative`, `create_*_carousel`, `generate_creative_image`, `expand_to_stories`, `batch_request`, `send_capi_event`. docs/02 сам признаёт, что в базовом Pipeboard (29 инструментов) их нет. Значит, если идти строго по QUICKSTART, получится сервер, на котором часть скиллов не работает.

**Токен и права**
- System User в Business Manager с ролью **Admin**. Ему выдают **Full control** на приложение, на все выбранные рекламные аккаунты и на страницы (docs/00, шаги 10–11).
- Разрешения токена в разных документах разные:
  - README и QUICKSTART: `ads_management`, `ads_read`, `pages_manage_ads`;
  - docs/00 добавляет `pages_read_engagement` и `business_management`;
  - docs/02 предлагает ещё вариант с обычным токеном из Marketing API → Tools, живущим около 60 дней.
- Нужен Meta App типа Business с продуктом Marketing API в статусе Live. По словам автора, без Live нельзя создавать креативы через API. QUICKSTART обещает «3–5 часов» на всё и тут же пишет про 1–3 дня ожидания.
- Токен бессрочный, живёт до отзыва.

**Где хранится.** Открытым текстом в `.mcp.json` в корне проекта, вместе с App Secret и ключом Gemini. `.gitignore` исключает `.mcp.json`, `*.env`, `.env*`, `config/tokens.md`. Но docs/00 советует скачивать ZIP, без git, и тогда `.gitignore` ни от чего не защищает. Кроме того, README предлагает обходить баг `upload_ad_image` вызовом curl напрямую, так что токен попадает ещё и в командную строку и историю shell.

**Сравнение с нашим официальным коннектором** (`https://mcp.facebook.com/ads`, OAuth, custom connector в claude.ai)

| | Репо (локальный MCP + System User) | Официальный Meta MCP (наш) |
|---|---|---|
| Вход | бессрочный токен Admin System User и App Secret в файле | OAuth под учёткой человека, секретов на диске нет, доступ отзывается в настройках Facebook или claude.ai |
| Настройка | Mac, brew/uv/python/node, свой Meta App в Live, System User; часы работы и дни ожидания | добавить коннектор и войти |
| Защита | только текст промпта | на стороне сервера: всё создаётся PAUSED; правила владельца портфеля (у нас ≤$30 на кампанию и ad set, лимит аккаунта $200) |
| Инструменты | около 47 (форк), включая Gemini-картинки и batch | около 96, включая бенчмарки, аномалии, opportunity score, Ad Library, help-статьи, A/B, журнал активности; генерации картинок нет |
| Где работает | только Claude Code (CLI или VS Code) | claude.ai (веб и мобильный); возможно, и Claude Code как удалённый HTTP MCP с OAuth (проверить) |
| Автономность | можно запускать по расписанию без человека | нужен живой сеанс; для нас это скорее плюс |
| Кто поддерживает | форк неизвестного автора, BSL | Meta |

**Минусы и оговорки официального коннектора для нас**
1. OAuth-сессия видит **все** рекламные аккаунты, к которым у человека есть доступ. В инструкции нужно разрешить только `1004461399321073` и в начале каждого сеанса сверять аккаунт через `Ads get ad accounts`.
2. Доступ привязан к личной учётке: человек уходит — доступ пропадает.
3. Точный состав и параметры инструментов нам известны не полностью: поиск интересов и гео, lookalike, пресеты дат, уровни insights. Нужно проверить.
4. Есть `Ads activate entity`, то есть Claude технически может включить показ. Запрет нужно закрепить в инструкции. Если claude.ai позволяет задавать разрешения по отдельным инструментам, этот инструмент лучше перевести на ручное подтверждение или отключить (проверить).
5. Нужно проверить, действует ли правило «≤$30» и на изменение через `Ads update entity` (повышение бюджета), или только на создание.

**Чем опасно хранить токен так, как в репо.** Бессрочный Admin-токен с Full control на все аккаунты и страницы лежит в открытом файле. Утечь он может через:
- бэкап или облачную синхронизацию (наша рабочая папка на Google Drive, так что `.mcp.json` уехал бы в облако);
- скриншот или показ экрана;
- чтение файла самим агентом (prompt injection из данных может выманить токен).

Отозвать его можно только перевыпуском. Вариант с Pipeboard вообще отдаёт токены Facebook третьей стороне.

## 3. Двенадцать скиллов

Общее для всех: триггер задаётся только полем `description` во фронтматтере (по-русски, общими словами) или командой `/name`. Описание ads-agent («анализ, оптимизация, создание кампаний, отчёты») пересекается со всеми остальными, так что маршрутизация размыта.

### 3.1 ads-agent (`skills/ads-agent/SKILL.md`)
- **Назначение:** оркестратор, почти дословная копия `config/AGENT.md`, но с путями `.claude/ads-agent/`.
- **Триггер:** «Вызывай для анализа, оптимизации, создания кампаний и отчётов», команда `/ads-agent`.
- **Алгоритм:**
  1. Определить аккаунт по `ad_accounts.md`.
  2. Прочитать бриф.
  3. Передать задачу нужному скиллу: optimizer, campaign-manager, reporter, creative-analyzer, copywriter, image-generator, targeting. dashboard, onboarding, naming и delete в этом списке не названы.
  4. Перед оптимизацией прочитать историю за 3 дня.
  5. Перед «опасной» операцией показать план в формате «Планируемые действия: 1. [Действие] — [Причина] … Продолжить? (да/нет)».
  6. После операции записать лог.
- **MCP (перечислены «46 tools»):** `get_ad_accounts`, `get_campaigns`, `get_adsets`, `get_ads`, `get_insights`, `get_ad_creatives`, `get_custom_audiences`, `pause_campaign`/`resume_campaign`, `pause_adset`/`resume_adset`, `pause_ad`/`resume_ad`, `update_adset`, `create_campaign`, `create_adset`, `create_ad`, `search_interests`, `search_geo_locations`, `search_demographics`, `estimate_audience_size`, `create_lookalike_audience`, `upload_ad_image`, `upload_video`, `create_ad_creative`, `create_*_carousel`.
- **Опасными считает:** бюджеты, паузу и возобновление, создание кампаний, «всё, что влияет на расходы».
- **Пишет в файлы:** `history/YYYY-MM/YYYY-MM-DD.md` (формат в §1).

### 3.2 ads-optimizer (`skills/ads-optimizer/SKILL.md`, самый большой, 24 КБ)
- **Назначение:** ежедневная оптимизация бюджетов и пауза «пожирателей». Цели прописаны прямо: держать суточный бюджет аккаунта и направлений и выходить на плановый CPL каждого направления.
- **Триггер:** «анализ метрик, Health Score, ad-eater detection, рекомендации по бюджетам», `/ads-optimizer [account]`.
- **Алгоритм (12 шагов):**
  1. **Выбор аккаунта.** Показать таблицу аккаунтов; шаг пропускается, если аккаунт передан аргументом.
  2. **История за 3 дня.** Учесть, что менялось, возраст объектов (обучение 48 ч), паттерн «3 снижения за 3 дня → пауза», запрет качелей.
  3. **Сбор данных.**
     - Бриф и обязательно `creatives.md` («без него к анализу не переходить»).
     - `get_campaigns(status_filter="ACTIVE")`, `get_adsets`.
     - `get_insights` на уровне adset за today, yesterday, last_3d, last_7d. В тексте написано «5 периодов ОБЯЗАТЕЛЬНО», а вызовов 4: last_30d нет, хотя тренд 7d vs 30d без него не посчитать.
     - На уровне ad: yesterday и last_7d.
  4. **Направления.** Направление — это кампания с `Campaign ID` из таблицы брифа, у неё свой «Цель CPL» и свой «Бюджет». Сумма бюджетов активных адсетов не должна превышать бюджет направления. Бюджеты направлений между собой не суммируются.
  5. **Health Score** (детали в §4, здесь своя версия с отличиями):
     - CPL-разрыв: +45 / +30 / ±10 / −30 / −45;
     - тренд 3d vs 7d: до ±15;
     - диагностика: CTR < 1% → −8, CPM > медианы на 30% → −12, Frequency 7d > 2 → −10;
     - «новизна» (< 48 ч): не больше −10 и/или множитель 0.7;
     - объём: 0.6…1.0 (при < 1000 показов ближе к 0.6, при > 5000 ближе к 1.0);
     - компенсация по сегодняшнему дню при ≥ 300 показах: CPL сегодня ≤ 50% вчерашнего → полная компенсация плюс бонус; ≤ 70% → 60%; ≤ 90% → +5;
     - классы: ≥ +25 very_good, +5…+24 good, −5…+4 neutral, −25…−6 slightly_bad, ≤ −25 bad.
  6. **Пожиратели (ad-eaters)** здесь — именно объявления, не адсеты:
     - CRITICAL: CPL > 3× цели → немедленная пауза;
     - HIGH: ноль лидов при тратах ≥ 2× цели → пауза;
     - HIGH: CPL > 2× и доля трат ≥ 50% → пауза;
     - MEDIUM: CPL > 1.5× и доля ≥ 50% → «пауза с осторожностью»;
     - рабочая логика: в адсете с ≥ 2 объявлениями берут главного тратящего; если у него ≥ 50% трат и CPL > 1.3× цели, он пожиратель;
     - если пауза опустошит адсет, объявление не трогают, а адсет ставят на паузу только при HS ≤ −25.
  7. **Матрица действий:**
     - very_good → +10…+30%; good → держать или +0…10%; neutral → наблюдать; slightly_bad → −20…−40%; bad → −50% или пауза.
     - Снижение по отклонению CPL от цели: +10…30% → −15…−25%; +30…50% → −25…−35%; +50…100% → −35…−45%; +100…200% → −50%; больше +200% → пауза.
     - Запрещено: снижать на −50% при отклонении меньше +100%, на −40% при отклонении меньше +50%, ставить на паузу при отклонении меньше +200%.
     - Минимальный бюджет $3.
  8. **Креативы (помечено «обязательно всегда»).** Найти креативы из `creatives.md`, которые нигде не используются, и предложить под них новые адсеты. Условия: есть неиспользуемый креатив, освободилось ≥ $10, или направление недобирает бюджет (< 95%). Предлагать, «даже если бюджет в норме».
  9. **Балансировка.**
     - Коридор 95–105% плана по каждому направлению; ниже 95% считается «ОШИБКОЙ», и нужно добавить повышения или создать адсеты.
     - Освободившийся бюджет: < $10 → отдать лучшим; $10–20 → 1 новый адсет; $20–35 → 2 адсета по $10–17; ≥ $35 → 3 адсета по $10–15.
     - «Лучший из плохих»: если нет HS ≥ +25, лучшему из оставшихся +10…20% (не больше 30%).
     - Новый адсет: имя `{creative_tag}_{YYYY-MM-DD}` (кириллица разрешена), бюджет $10–20 и не больше $20, не более 3 новых на направление за запуск, внутри кампании направления.
     - Шаблон вызова: `create_adset(..., optimization_goal="OFFSITE_CONVERSIONS", billing_event="IMPRESSIONS", targeting={...})`, где targeting взят «из config или default», то есть не определён.
  10. **Вывод в markdown:** сводка по направлениям, пожиратели, детали, итоговые действия и вопрос «Выполнить? (да / нет / частично)».
  11. **Выполнение:** `update_adset(daily_budget в центах)`, `pause_adset`, `pause_ad`, `create_adset`.
  12. **Лог** в history.
- **Метрики по типу кампании:**
  - WhatsApp: conversations_started, quality_leads (≥ 2 сообщений);
  - сайт: pixel_leads;
  - лид-формы: form_leads;
  - трафик в IG: CPC, а не CPL.
- **Ограничения:** бюджеты в центах, 300…10000 ($3…$100); шаг +30% / −50%; работать только с ACTIVE; «включать кампании нельзя, только пользователь»; кампании с CBO и адсеты с lifetime-бюджетом не трогать.
- **Веса периодов:** ночной режим — Y 55% / 3d 30% / 7d 15%; дневной — T 55% / Y 30% / 7d 15%. В формулу HS они никак не встроены. Минимальная база: ≥ 1000 показов на адсет.
- **Пишет в файлы:** history.

### 3.3 ads-reporter (`skills/ads-reporter/SKILL.md`)
- **Назначение:** дневные и недельные отчёты, сравнение периодов, аудитории.
- **Триггер:** «дневные/недельные отчёты, сравнение периодов, тренды». Примеры запросов: «Отчёт за сегодня», «Недельный отчёт», «Сравни эту неделю с прошлой», «Анализ по возрастам», «Какие adsets лучше».
- **MCP:** только `get_insights`.
  - Пресеты: today, yesterday, last_3d, last_7d, last_14d, last_30d, this_month, last_month и свой диапазон `{since, until}`.
  - Уровни: account, campaign, adset, ad.
  - Разбивки: age, gender, country, device_platform, publisher_platform.
- **Алгоритм:**
  1. Аккаунт и бриф.
  2. Пять периодов «параллельно» на уровне adset, плюс ads за yesterday.
  3. Посчитать CPL, CTR и HS.
  4. Заполнить шаблон.
  5. Добавить выводы и рекомендации.
- **Шаблоны:**
  - **Дневной:** today против вчера (темп), вчера против позавчера и против среднего за 7 дней, блок компенсации по сегодняшнему дню, адсеты с HS, лучшие объявления с Risk, проблемы.
  - **Недельный:** сводка (включая ROAS), CPL по дням недели, HS с колонками компонентов, разбор худших, лучшие и худшие, рекомендации.
  - **Аудитории:** возраст, пол, площадки.
  - **Неделя к неделе:** last_7d против своего диапазона. **Месяц к месяцу:** this_month против last_month.
- **Пороги:**
  - хорошо: CTR > 1% (отлично > 2%), CPL < цели (отлично < 0.7×), Frequency < 3 (отлично < 2), LP view rate > 60% (отлично > 80%);
  - тревога: CPL > 1.5× (критично > 2×), Frequency > 4 (критично > 7), CTR < 0.5% (критично < 0.3%), траты без лидов > $10 (критично > $20);
  - стрелки тренда: ±10% считается «стабильно», ↓↓ при изменении > 30%.
- **Пишет в файлы:** ничего, хотя QUICKSTART обещает HTML в `reports/`.
- **Замечание:** в примере недельного отчёта ошибка в арифметике: −30 −7.5 −8 +20 = −25.5, а в таблице стоит −22 и класс slightly_bad.

  - `special_ad_categories`;
  - UTM-меток.
- В примере лид-формы, по нашим данным, не хватает `promoted_object` (page_id) и `lead_gen_form_id` в креативе. Проверить.

### 3.6 targeting-expert (`skills/targeting-expert/SKILL.md`)
- **Назначение:** интересы, lookalike, гео, демография, оценка размера аудитории.
- **Триггер:** «поиск интересов, Lookalike, гео, демография».
- **MCP:**
  - `search_interests(query, limit=25)`, `get_interest_suggestions(interest_list, limit)`;
  - `get_custom_audiences`, `create_lookalike_audience(seed_audience_id, country, ratio)`;

  - `search_demographics(demographic_class=demographics | life_events | industries | income)`;
  - `estimate_audience_size(targeting, optimization_goal="REACH")`.
- **Алгоритм:**
  1. Бриф: кто клиент.
  2. Поиск интересов по схеме «широкие → конкуренты → смежные → нишевые».
  3. Оценка размера аудитории.
  4. Сборка объекта targeting.
  5. Рекомендации: расширить, улучшить качество, новые аудитории для теста.

- **Стратегии:**
  - холодная аудитория: интересы на 500K–2M, LAL 1–3%, Advantage+ «для зрелых аккаунтов»;
  - тёплая: посетители сайта за 7, 14 и 30 дней, досмотры видео 25/50/75%, вовлечённые, список клиентов.
- **Ошибка, важная для нас:** в примере `"locales": [{"id": 6}]` с комментарием «Russian». По нашим данным locales задаются массивом чисел, а ключ 6 — это English (US). Ключ русского языка нужно искать поиском локалей. Проверить.

### 3.7 creative-analyzer (`skills/creative-analyzer/SKILL.md`)
- **Назначение:** Risk Score креативов, группировка по тегу, выгорание, A/B, визуальный разбор.
- **Триггер:** «оценка креативов, Risk Score, A/B». Примеры запросов: «Какие креативы работают лучше?», «Какие пора менять?», «Настрой A/B тест», «Добавь новый креатив в реестр».
- **MCP:** `get_ads(limit=50)`, `get_insights(last_7d и last_30d, level="ad")`, `get_ad_creatives(ad_id)`, `get_ad_image(ad_id)`.
- **Алгоритм:**
  1. Список объявлений с метриками за 7d и 30d.
  2. Risk Score для каждого.
  3. Тренд 7d vs 30d: ↑ при CPL_7d < CPL_30d; ±10% стабильно; ↓↓ при превышении > 1.3×.
  4. Сортировка, лучшие и худшие.
  5. Рекомендации.
- **Risk Score (0–100, чем выше, тем хуже):**
  - база 50;
  - CPL > 2× → +25, > 1.3× → +15, < 0.7× → −20;
  - CTR < 0.5% → +15, > 2% → −10;
  - CPM > медианы × 1.5 → +15;
  - ROI > 100% → −25, 50–100% → −10, < 0% → +30;
  - классы: 0–25 масштабировать, 26–50 следить, 51–75 оптимизировать, 76–100 пауза.
  - В примере ошибка: 50+25+15+15+30 = 135 (то есть 100), а подписано «82».
- **Группировка:** `creative_tag = ad_name.split("_")[0]`, сумма spend, impressions, clicks, conversions, расчёт CPL, CTR, CPM, сверка с `creatives.md`.
- **Метрики креативов:**
  - CTR: хорошо > 1%, плохо < 0.5%;
  - Thumb stop: хорошо > 25%, плохо < 15%;
  - Hook (3-секундные просмотры / запуски): хорошо > 30%, плохо < 20%;
  - Hold: хорошо > 15%, плохо < 5%.
  - В глоссарии формулы Hook и Hold другие.
- **Выгорание:** Frequency > 4, падение CTR > 20% за неделю, рост CPL > 30% за неделю, падение показов при том же бюджете.
- **A/B:**
  - правила: одна переменная, ≥ 1000 показов на вариант, 7 дней, ≥ 3 конверсий, значимость 95%;
  - но «победитель» определяется правилом «разница CPL > 20% и > 1000 показов → значимо». Это не статистика.
- **Визуальный чек-лист** включает «текст < 20% площади». Это правило Meta давно отменено.
- **Пишет в файлы:** обновляет `config/creatives.md` по запросу «добавь в реестр».

### 3.8 creative-copywriter (`skills/creative-copywriter/SKILL.md`)
- **Назначение:** рекламные тексты. Роль прописана как «копирайтер AI-агентства Performante».

- **Реестр креативов:** сначала искать `video_id`, потом `creative_id` в `config/creatives/{account}/index.md` (такой папки нет). Если найдено, повторно не загружать. Один `video_id` используется для всех типов кампаний.
- **campaign_type и нужные поля:** WhatsApp (phone, question), LeadForm (form_id), Website (link_url), Instagram (instagram_actor_id).
- **Лог:** та же таблица, что в §1. Пример процесса из 11 шагов, от «прочитать историю» до «залогировать».

### 4.2 safety_rules.md — все правила кратко
1. **Критичные операции, всегда спрашивать:** изменение бюджета, пауза кампании, адсета или объявления, создание кампании, любое удаление, изменение таргетинга.
2. **Средний риск, показать план:** возобновление, дублирование, смена bid strategy. Неясно, нужно ли тут подтверждение.
3. **Без подтверждения:** чтение метрик, отчёты, поиск интересов и локаций.
4. **Шаг бюджета:** не больше +30% и не больше −50% за раз. Пример: $20 → максимум $26 или минимум $10.
5. **Абсолютные границы (если в брифе нет других):** адсет от $3 до $100 в день; новый адсет $10–20 в день.
6. **Время:** не создавать адсеты после 18:00 по часовому поясу аккаунта, кроме срочного явного запроса.
7. **Обучение около 7 дней:** не менять бюджет и таргетинг без критической причины.
8. **Минимум данных для решения по бюджету:** 1000 показов, 3 конверсии, 2 дня с данными. Для решений по сегодняшнему дню: 300 показов и $3 трат. Если меньше — ждать.
9. **Пожиратели:** CPL > 3× цели → немедленная пауза; > 2× и > 50% трат → −50% бюджета; > 1.5× → следить.
10. **История за 3 дня:**
    - объекты моложе 48 ч не трогать агрессивно (кроме CPL > 3×);
    - вчера уже снижали — не снижать снова (кроме роста CPL в 3+ раза);
    - 3 снижения за 3 дня → пауза вместо снижения;
    - вчера повышали — сегодня не снижать (кроме роста CPL в 2+ раза);
    - сегодня лучше, чем вчера → наблюдать вместо снижения.
11. **История — контекст, а не запрет:** при CPL в 5× цели действовать немедленно. Всегда логировать.
12. **Перед действием проверить:** тот ли аккаунт, тот ли объект, соблюдены ли лимиты, хватает ли данных.
13. **При ошибке:** сразу сообщить, попытаться откатить, записать в историю.
14. **Чек-лист из 9 пунктов** перед опасной операцией: история, бриф, цели, данные, правила истории, лимиты, план показан, подтверждение получено, действие залогировано.
- Путь к истории здесь `.claude/ads-agent/history/`, а в CLAUDE.md `history/`.

### 4.3 fb_best_practices.md
- **Структура:** Campaign по цели или направлению → AdSet по аудитории → Ad по креативу. Нейминг `{Направление}_{Цель}_{Дата}` / `{Аудитория}_{Возраст}_{Гео}` / `{Креатив}_{Версия}`. Это третий вариант нейминга в репо.
- **ODAX:** Awareness, Traffic, Engagement, Leads (формы и WhatsApp), Sales, App.
- **Аудитории:** шкала размеров как в targeting-expert. Advantage+ «рекомендуется для большинства случаев». Lookalike 1% / 1–3% / 3–5% / 5–10%.
- **Бюджеты:**
  - CBO при 3+ похожих адсетах; не использовать для тестов, разных целей и когда нужен контроль;
  - минимумы в день: показы и охват $1, клики $2, конверсии $5 (лучше $10+), установки $5.
- **Обучение:**
  - нужно около 50 конверсий за 7 дней;
  - минимальный дневной бюджет = 50 × целевой CPA / 7;
  - во время обучения не менять бюджет больше чем на 20%. Это противоречит safety_rules (там «не менять» и шаг 30%).
- **Креативы:**
  - Single image, Carousel, Video, Collection;
  - 1:1 1080×1080 для ленты, 9:16 1080×1920 для Stories и Reels;
  - primary text 125 знаков, headline 27, description 27;
  - эмодзи умеренно, один CTA.
- **A/B:** одна переменная, ≥ 1000 показов на вариант, ≥ 7 дней, значимость > 95%; проигравшего останавливать при CPL > 2× победителя.
- **Масштабирование:** по бюджету +20–30% раз в 2–3 дня и не во время обучения; горизонтально — дубль адсета с новой аудиторией на $10–20.
- **Типовые проблемы:** высокий CPM (узко, конкуренция, креатив), низкий CTR (креатив, аудитория, текст), высокий CPL (лендинг, трафик, оффер).
- **Сезонность CPM:** Black Friday +50–100%, Новый год +30–50%, 8 Марта +20–30%, конец квартала +10–20%. Креативы готовить за 2 недели.

### 4.4 metrics_glossary.md
- **Формулы:** CPL = Spend / Leads; CPA; ROAS = Revenue / Spend; CTR; CPC; CPM = Spend / Impr × 1000; Frequency = Impr / Reach; Link CTR; LP View Rate = LPV / Link clicks; CR = Conv / Link clicks.
- **Пороги:**
  - CPL: < цели отлично; до 1.5× норма; 1.5–2× выше нормы; 2–3× снижать; > 3× пожиратель, пауза;
  - ROAS: > 3 отлично; 2–3 хорошо; 1–2 на грани; < 1 убыток;
  - CTR: > 2% отлично; 1–2% хорошо; 0.5–1% средне; < 0.5% плохо;
  - **CPM: < $5 дёшево; $5–15 норма; $15–30 дорого; > $30 «проверь таргетинг»** — это цифры рынка СНГ, для США они не подходят;
  - Frequency: 1–2 норма для холодной аудитории; 2–4 для тёплой; > 4 выгорание; > 7 критично;
  - LP View Rate: > 80% отлично; 60–80% норма; < 60% медленный сайт.
- **Health Score:** `HS = clamp(round((CPL_Gap + Trends + Diagnostics + Today_Adj) × Volume_Factor), −100, +100)`.
  - CPL Gap по отношению факт/цель: ≤ 0.7 → +45; ≤ 0.9 → +30; ≤ 1.1 → +10; ≤ 1.3 → −30; > 1.3 → −45; ноль лидов при тратах ≥ 2× цели → −45.
  - Trends: 3d vs 7d и 7d vs 30d, каждый ±7.5 (ухудшением считается превышение > 1.1×).
  - Diagnostics: CTR < 1% → −8; CPM > медианы × 1.3 → −12; Frequency > 2 → −10.
  - Today_Adj при ≥ 300 показах сегодня: ≤ 0.5× вчерашнего → полная компенсация + 15; ≤ 0.7× → 60% + 10; ≤ 0.9× → +5. Если вчера было 0 лидов, сравнивают с целью: ≤ 0.7 → полная + 15; ≤ 1.0 → 70% + 10; ≤ 1.3 → 30%.
  - Volume Factor по вчерашним показам: ≥ 1000 → 1.0; ≤ 100 → 0.6; между ними линейно.
  - Противоречия: в таблице компонентов Today_Adj «+0…+30», а в примере 2 он равен +60; в примере 1 остался черновик.
- **Risk Score:** как в §3.7.
- **Метрики видео:** Thumb stop и Hook — обе считаются как 3-секундные просмотры / показы (одна и та же формула). Hold = просмотры до X% / запуски.
- **Уровни:** account, campaign, adset, ad. **Периоды:** today, yesterday, last_3d, last_7d, last_14d, last_30d, this_month, last_month. **Разбивки:** age, gender, country, device_platform, publisher_platform. Требование «нужны все 5 периодов».

### 4.5 troubleshooting.md
- **Аккаунт заблокирован:** выяснить причину, подать апелляцию, новый аккаунт не создавать.
- **Лимит расходов:** `get_account_info` → spending_cap, поднять или «подождать сброса 1-го числа». По нашим данным, лимит расходов аккаунта сам не сбрасывается. Для нашего лимита $200 это важно; проверить через `Ads get help article`.
- **Кампания не тратит:** узкая аудитория (< 100K), низкая ставка, CTR < 0.5%, проблемы с пикселем, Learning Limited. Для Learning Limited: бюджет до 50 × CPA / 7, расширить аудиторию, оптимизировать на более раннее событие, объединить адсеты.
- **Отклонение креатива:** «текст > 20%» (устарело), до/после, личные характеристики, запрещённые категории, «гарантированный результат».
- **Пиксель:** Events Manager, Pixel Helper, GTM, CAPI, Test Events.
- **Много кликов и мало заявок:** LP View Rate < 60%, нерелевантный трафик, плохой лендинг, сломанная форма.
- **Пересечение аудиторий.** LAL не работает при seed < 1000 или низком качестве seed; начинать с 1%.
- **Ошибки API:**
  - 17 (rate limit): подождать 1–5 минут, batch, кэш;
  - 100 (неверный параметр): формат `act_`, существование объекта, права;
  - 190 (токен): `get_login_link`;
  - 1487390: «сначала активировать `resume_adset`». Совет опасный: чтобы что-то поправить, включают показ.
- **Чек-лист диагностики:** статусы → бюджет и лимиты → аудитория → креатив → расписание, площадки, стратегия ставок.

### 4.6 naming_convention.md
- Имя объявления `{creative_tag}_{описание}`. Тег — первое слово до `_`, только латиница, одно слово до 15 знаков, совпадает с именем файла без расширения.
- Задача: суммировать статистику по креативу (пример: kitchen, $330, 70 лидов, CPL $4.71).
- Использование заявлено в analyzer, reporter и campaign-manager; реально есть только в analyzer.

## 5. Шаблон брифа (`config/briefs/_template.md`) и примеры

**Поля шаблона**
- **Бизнес:** ниша, продукт, регион, ЦА (возраст, пол, интересы), сайт или лендинг.
- **Цели:** основная цель (лиды, продажи, трафик, охват), вид конверсии (лид-форма, WhatsApp, звонок, покупка), целевой CPL/CPA «$X–$Y», целевой ROAS.
- **Бюджет:** дневной мин–макс, месячный лимит, минимум и максимум на адсет.
- **Правила оптимизации:** минимум показов 1000, минимум конверсий 3, порог пожирателя (обычно 3× цели), шаг +30% / −50%, часовой пояс, «не создавать адсеты после 18:00».
- **Активные кампании и направления:** таблица «Название | Campaign ID | Цель | Статус».
- **Креативы:** что работает лучше, стиль, тексты, CTA.
- Заметки и история изменений.

**Чего не хватает относительно того, что ждут скиллы**
- В таблице направлений нет колонок «Бюджет» и «Приоритет», а optimizer строит на них балансировку.
- Нет полей «Тон», «Преимущества» и «Боли» (нужны copywriter), «Гео-локации» (на них ссылается geo_locations), технических ID (Pixel, Form, WhatsApp).
- Онбординг генерирует бриф в другом, более богатом формате. Итого в репо два формата брифа.

**`examples/briefs/example_dental.md`**
- Стоматология в Варшаве: импланты, виниры, брекеты.
- Лид-формы, CPL $3–6, $50–150 в день, лимит $5000 в месяц, адсет $10–50, пожиратель при CPL > $15, UTC+1.
- Три направления с Campaign ID и своими целями CPL.
- Креатив «видео до/после». Это противоречит собственному troubleshooting и правилам Meta о здоровье.
- Заметки: женщины 30–45, LAL лучше интересов, сезонность.

**`examples/briefs/example_ecommerce.md`**
- Товары для дома в США, пиксель; «CPL» $2–4 на AddToCart; ROAS минимум 3×, цель 5×.
- $100–300 в день, $20 000 в месяц, адсет $20–100.
- Пороги строже: 2000 показов и 5 конверсий; пожиратель при CPL > $10 или ROAS < 1.5×; шаг −40%; UTC−4 (NY); не создавать после 20:00.
- Четыре кампании, события пикселя; средний чек $80, LTV $200, пик в пятницу–воскресенье.

В обоих примерах поле «Сайт/Landing» пустое.
