## 1. Кто говорит, о чём, для кого

**Ведущий** — «Влад», автор обучения, внутри которого идёт эфир. Фамилия в субтитрах не звучит. Домашние задания этого обучения: «ДНК клиента», «ДНК бизнеса», «оффер по Хормози» [43:24], [97:23], [98:28]. Возможно, это Влад Яско, но транскрипт этого не подтверждает. **Со-ведущий** — Влад Емельянов, «продакт-оунер» направления AI-таргета: изучал платформы и SaaS, пилит свою [10:31–10:51]. **Гость** — Сергей Харьковщенко [11:17], [13:40]. В таргете с 2014 года [15:13]. Компания в субтитрах звучит как «три маркетинг групп» [15:30] и «Dream Marking Office» [141:45], то есть, судя по всему, Dream Marketing Group. Три направления: performance-агентство (трафик), международный инфобиз (запуски с экспертами из США, Европы, Великобритании), цифровые продукты: воркбуки, гайды [15:30–16:34].

**Формат.** Живой стрим-урок внутри платного обучения ведущего. Звучат «домашнее задание по обучению», «предыдущие блоки обучения», «контентный блок» [98:28], [114:46], [118:46], [151:23]. «Воркшоп №10» и название курса «AI-маркетолог» в транскрипте не произносятся. «AI-маркетолог» звучит только как название одного из агентов Сергея [146:55–147:44]. Репозиторий skipaoff/ai-target-agent по имени не называют: говорят «ссылка на GitHub», её закрепили в чате [16:46], [45:04], [47:01].

**О чём.** Сергей показывает AI-агента-таргетолога на Claude Code, которым ведёт рекламу в своём агентстве. Затем вживую проходят подключение к Meta (приложение разработчика, System User, токен) и онбординг проекта одного из участников с первым медиапланом. Практику разбили на два эфира: в этом — установка и подключение до этапа креативов, запуск рекламы — на следующем стриме [13:02–13:34], [133:56–134:57].

**Для кого.** Участники обучения, в основном эксперты и малый бизнес с лендингом. По оценке ведущего, 60–70% аудитории — эксперты с сайтом и кнопкой «записаться на диагностику» или воронкой [119:22–119:57]. Уровень — «ничего не понимаю в таргете».

## 3. Техническая установка

### 3.1 Инструменты
- **Claude Code в десктоп-приложении Claude.** New Session, среда обязательно «local» [46:51–46:58]. Ведущий заранее оговаривает: у аудитории есть Claude Code Desktop, GitHub и умение ставить MCP-коннекторы [45:39–45:50].
- Начинать рекомендуют с **локальной версии** [46:42–46:50]. Всего вариантов три: файлы на ноутбуке; «через сервер», когда всё хранится и обновляется на GitHub; у Сергея — Obsidian плюс GitHub [25:53–26:37].
- **Модель** большой роли не играет (раздел 9).
- **Claude в Chrome** используют для исследования сайта или Instagram на онбординге [109:01–110:27].
- **Cowork** пробовали для кликов в интерфейсе Meta: «очень долго», руками быстрее [57:44–58:10].

### 3.2 Установка агента
1. Новая локальная сессия Claude Code: ссылка на GitHub плюс промпт «проанализируй, установи локально, проведи по этапам» (текст в разделе 7) [47:01–47:21].
2. Claude заходит в репозиторий, анализирует файлы, создаёт папку и структуру. В агенте есть файл установки, разбитый на пункты; Claude проверяет каждый и подсказывает, что делать [47:24–48:13], [49:08–49:37].
3. У Сергея есть инструкция в Notion: фазы от 0 до 7, «до первого запуска кампании» [48:31–48:48]. В эфире начали с фазы 2 [48:51–49:03].
4. Если Claude просит поставить Homebrew, можно поручить установку ему самому или выполнить выданную команду в терминале [88:55–89:37].

### 3.3 Что нужно в Meta заранее
- Facebook-аккаунт без ограничений и Business Manager. Без БМ приложение «может не дать создать» [51:01–51:07]. По словам Сергея, БМ обычно появляется сам при связке Instagram с Facebook [51:46–51:58].
- В Meta for Developers входить только через Facebook, не через Instagram [55:01–55:14].
- Нужны рекламный кабинет, страница Facebook, Instagram; пиксель — по ситуации (раздел 5). Создание кабинета или БМ и пополнение баланса вынесены «за скобки» [45:58–46:32], [52:01–52:12].

### 3.4 Приложение в developers.facebook.com
1. My Apps → Create App [52:14–53:14]. Через это приложение агент управляет кабинетом и БМ [53:18–53:37].
2. Название, например «AI таргетолог». App contact email — почта Facebook-аккаунта: туда приходят коды подтверждения [54:30–54:54].
3. Use cases: первые два пункта «Create and manage…». Со слов Сергея, это управление «через маркетинг» и рекламой «через Meta Ads Manager» [55:26–56:04]. Точные названия субтитры не передали.
4. Выбрать один основной БМ. Агентство тоже выбирает один основной, остальные БМ, кабинеты и страницы открываются на него [56:10–56:55].
5. Requirements пустые; Overview → Create app → пароль Facebook [57:03–57:14].
6. На дашборде приложения серые галочки нужно сделать зелёными. Для каждого Customize: открыть страницу, прокрутить вниз, вернуться назад. С Test так же [58:13–60:32].
7. Следующий пункт требует **Privacy Policy URL и Terms of Service URL** → Go to App Settings (Basic) [60:36–61:13].
   - Сохранить **App ID и App Secret** (Show → скопировать) в заметки: их потом отдают Claude [61:15–61:59], [70:48–71:09].
   - Ссылки делают на бесплатном генераторе политик: ссылку дали в чате, по субтитрам это Free Privacy Policy [66:46]. Порядок: тип App → название приложения → Entity type: Individual → страна US или Ukraine («в Ukraine лишних полей нету») → из данных собираем только email → на остальные вопросы «нет» → связь по email (та же почта) → Generate → скопировать ссылку [62:21–64:52]. Затем то же для Terms [66:39–67:00].
   - Страна в генераторе не обязана совпадать с гео рекламы: Сергей выбирает Украину и крутит рекламу на США и UK [63:06–63:24].
   - Политику со своего сайта ставить «можно, но не нужно»: она «может не мэтчиться» [67:20–67:37].
   - Зачем всё это: без ссылок приложение не опубликовать. Неопубликованное приложение «ограничено»: обслуживает мало кабинетов, и Claude рано или поздно ответит «нет доступа» или «не хватает разрешений» [65:11–66:00].
8. Save changes, выбрать страну → вкладка Publish → Publish [68:47–70:39].

### 3.5 System User и токен (business.facebook.com)
1. Users → System users → Add. При первом создании нажать I accept [73:50–75:01].
2. Имя (тот же «AI таргетолог»), роль **Admin**: «очень важный пункт» [75:04–75:22]. Может запросить подтверждение по email или телефону [75:29–75:58].
3. Generate token → выбрать своё приложение [79:44–80:01]. Срок действия — **Never**, иначе «через 60 дней ваш таргетолог умрёт» [80:03–80:24].
4. «No permission available» на первом заходе — это нормально: у System User ещё нет активов [80:41–80:52].
5. Три точки у System User → назначить активы → рекламный кабинет → Full access. Ограничивать, по словам Сергея, «нет смысла»: это не живой таргетолог, который украдёт кабинет [81:04–82:23]. Страницу Facebook, Instagram и кабинет лучше выдать сразу [83:03–83:14].
6. **Ошибка в эфире:** повторная генерация снова дала «No permission». Причина: приложению не дали доступ к активам БМ. Решение: Accounts → Apps → своё приложение → подключить активы → выбрать кабинет → Done; затем Assign people → System User → Full access [83:25–85:03].
7. Generate token → Never → Select permissions: **ads_management, ads_read, business_management**. Остальное, по словам Сергея, «не надо» [85:32–86:05].
8. Подтверждение (email, телефон или приложение) → Submit. Токен показывают **один раз**, его надо сразу скопировать и сохранить [86:05–87:17]. Его можно отозвать (Revoke) и выпустить заново, например если истёк через 60 дней [87:27–87:57].
9. Позже агент одного из участников потребовал новый токен с дополнительными правами для креативов: pages_manage_ads, pages_read_engagement, права Instagram. Сергей: перевыпустить токен и «выбирайте всё сразу», «ничего критичного нету», потом обновить токен в Claude [130:58–132:24].

### 3.6 Передача ключей в Claude
- Нужны три значения: **App ID, App Secret, токен System User** [88:01–88:41]. Их вставляют в чат Claude Code, он «сохраняет и коннектит» и «прописывает специальные файлики» [88:41–88:48], [90:17–90:36]. В какой файл и как (`.mcp.json`, переменные окружения), в эфире не показывали.
- Сергей о безопасности: секреты в Claude Code вставлять можно, раз он «работает локально»; ключи «никуда не утекают», пока не попросишь их опубликовать. Ещё он говорит, что Claude Code теперь скрывает ключи в чате [103:40–104:24]. Критика в разделе 11.
- Проверка: Claude отвечает, что видит кабинет и страницы. После этого можно онбордить [96:43–97:10].
- Несколько БМ: один основной, остальные подключаются к нему через партнёрский доступ; одно приложение на один БМ [91:24–92:29].
- У ведущих на ключи ушёл «почти час», хотя кабинеты уже были готовы [89:54–90:03].

- Генератор политики «выбил на главную». Совет: пройти заново [66:04–66:41].
- Из Украины «отказано в доступе» к developers.facebook.com. Сергей считает, что дело в конкретном аккаунте (прошлые ограничения). Варианты: VPN или «купить уже готовый аккаунт» [72:38–73:45].
- Claude попросил поставить Homebrew [88:55–89:37].
- Агенту не хватило прав токена для креативов [130:58–132:24].
- Интерфейс Meta постоянно меняется, редизайн «пятнадцатый» [59:40–59:53].

### 3.8 Сверка с локальной копией репо (НЕ из видео)
Рядом лежит копия репо: README ссылается на github.com/skipaoff/ai-target-agent, заявлено «12 Skills», контакт в Telegram @dreamm_assistant. Что совпадает и что нет:
- Фазы 0–7 в QUICKSTART.md совпадают с «от нулевой до седьмой фазы» из эфира [48:42–48:48].
- **Подключение в репо идёт через сторонний open-source MCP-сервер `pipeboard-co/meta-ads-mcp`** (запуск через `uv`). Ключи вписывают в `.mcp.json` в папке агента, блок env: `META_APP_ID`, `META_APP_SECRET`, `META_ACCESS_TOKEN`. То есть «приложение плюс System User» — только способ получить токен, а сам агент всё равно работает через MCP. Противопоставление «MCP против приложения» из эфира [76:04–77:52] репо не подтверждает.
- Права в репо: ads_management, ads_read, **pages_manage_ads**. В эфире называли business_management, а pages_manage_ads всплыл позже, когда агенту не хватило прав на креативы [130:58–131:28].
- В репо тип приложения — Business с продуктом Marketing API, публикация (статус Live) «занимает 1–3 дня». В эфире новый интерфейс с use cases, и приложение опубликовали сразу.
- Онбординг в репо (skills/account-onboarding) — «~20 вопросов». В эфире — «9 блоков на 30 вопросов» [25:22–25:38]. Видимо, рабочая версия Сергея шире публичной.
- В репо есть скилл dashboard, хотя в эфире сказано, что дашбордов в базовой версии нет [19:54–19:57].
- В репо есть `config/knowledge/safety_rules.md`; в эфире о нём не говорили (раздел 6).

## 5. Как агент работает в бою

### Онбординг в демо
Агент задаёт вопросы с вариантами ответа [104:26–105:44]: чей проект и какая роль (выбрали «клиентский»); стадия и что важно (выбрали «докрутить оффер и копирайт»); формат работы. На формате у Сергея «хардовая» версия поднимает оркестратор с агентами маркетолога, продюсера и контентщика; в базовой вопросы проще, например «запуск рекламы» [105:00–105:34]. Дальше агент объявляет план: прочитать 7 документов, собрать медиаплан, проверить пиксель на лендинге, собрать креативы [111:23–111:37].

### Медиаплан v1 из демо
Бюджет $500. Проект участника — онлайн-заработок для русскоязычной украинской диаспоры в ЕС [105:44–105:49], [121:21–125:47].
- **Сценарий A** — пиксель работает, в истории есть покупки. Цель — конверсия «покупка»; гео — Германия, Польша, Чехия; языки русский и украинский; широкая аудитория плюс 2 lookalike, если есть база; плейсменты — автоматические Advantage+ [121:50–122:22].
- **Advantage+ Сергей велит «сразу тормозить».** Запретить агенту Advantage и оставить только мобильные плейсменты: сторис или сторис плюс лента [122:22–122:42]. Если не разбираетесь, на первом запуске можно довериться агенту, выделив, например, $20 [122:44–123:00].
- **Сценарий B** — новый пиксель без истории, «прогрев и сбор данных». Два адсета с оптимизацией не на покупку, а на просмотр контента и начало оформления (ViewContent и InitiateCheckout). Цель — прогреть аккаунт, пиксель и продукт и сэкономить бюджет [123:36–124:18].
- **Аудитории:** детальный таргетинг, custom audiences, lookalike [124:21–124:29].
- **Креативы:** в первом пакете 3 штуки [124:29–125:06], [132:27–132:45]. Сгенерированы Nano Banana через Higgsfield, модель агент выбрал сам [133:13–133:31]. К каждому готовы primary text, ссылка, CTA, headline и description [133:38–133:53]. Сергею они не нравятся, но «мы не знаем, как они пойдут» [132:50–133:03].
- **KPI и бенчмарки:** по каждой метрике три уровня, «плохо / хорошо / очень хорошо». Метрики: CTR, hook rate, CPC, стоимость просмотра страницы (в субтитрах неразборчиво), стоимость ViewContent, стоимость InitiateCheckout, CPA покупки [125:43–127:20]. Результаты можно показать агенту и спросить, хорошо это или плохо [128:13–128:32].
- **Что агенту нужно для запуска** (перечислил сам): ID кабинета; ID БМ; созданный пиксель; страница Facebook и Instagram (ссылки или ID); подключённый способ оплаты в БМ и кабинете; ожидаемый ROAS и допустимый CPA [129:43–130:31].
- **CPA:** агент заложил допустимые $150. Сергей: «меня устраивает 15 долларов... делай», и агент будто бы сам подстроит настройки под эту цену [130:31–130:55].

### Структура кампаний
- Уровень кампании: цель, событие конверсии, ABO или CBO, специальные категории. Уровень адсета: аудитория и плейсменты (Advantage вкл/выкл, мобайл или десктоп) [35:53–36:44].

## 6. Правила безопасности и ограничения, которые прозвучали

О безопасности говорили мало, и почти всё — в пользу максимальных прав:
- **Блокировки:** их «не будет», потому что приложение официальное, а System User создаётся в самой Meta. Единственная оговорка: «если вы не нарушаете политику» [53:46–54:24].
- **Права:** Full access на кабинет, ограничивать «нет смысла» [82:14–82:23]. Не хватает прав — «выбирайте всё сразу», «ничего критичного нету» [132:06–132:17]. Срок токена — Never [80:03–80:38].
- **Секреты** можно вставлять в чат Claude Code, раз он «работает локально» [103:57–104:24].
- **Что реально ограничивает агента** (из сказанного): базовая версия действует только по команде [136:57–137:22]; медиаплан утверждает человек, прежде чем сказать «запускай» [115:36–115:43]; дефолты агента, например Advantage, правит человек [122:22–122:42]; первый запуск на малую сумму, около $20 [122:52–123:00]; допустимые CPA и ROAS задаются явно [130:25–130:55].
- Ведущий несколько раз просит закрыть доступ к ссылке на GitHub. Мотив — чтобы методику не скопировали конкуренты, а не безопасность [16:46–17:02], [85:03–85:06], [140:37–141:30].
- Специальные категории объявлений упомянуты только как параметр кампании [36:06–36:11]. Правила Meta к содержанию объявлений не обсуждали.
- **Не обсуждали вообще:** лимит расходов аккаунта, дневные капы, создание кампаний на паузе, подтверждение перед тратой денег, журнал действий, ротацию и хранение токена.
- **Для контраста, из репо (не из видео):** `config/knowledge/safety_rules.md` требует подтверждения пользователя на создание кампаний, изменение бюджетов и таргетинга, паузу и удаление. Там же:
  - бюджет за раз меняется не больше чем на +30% / −50%;
  - бюджет адсета от $3 до $100 в день, у нового адсета $10–20;
  - новые адсеты не создаются после 18:00;
  - адсет в фазе обучения (~7 дней) не трогают;
  - для решений нужен минимум данных: 1000 показов, 3 конверсии, 2 дня;
  - «ad-eater»: CPL в 3 раза выше целевого → пауза;
  - все действия пишутся в журнал.

  В эфире ни одно из этих правил не прозвучало.

## 7. Промпты и формулировки (близко к тексту)

1. Узнать возможности: «распиши мне, что ты умеешь» [18:43].

**Утверждение Сергея о безопасности:** «никаких ограничений, никаких багов, блокировок не будет» [54:15–54:21].

## 9. Стоимость, тарифы и лимиты Claude

- О тарифах Claude, Claude Max, лимитах сообщений или токенов и о расходе **в эфире не сказано ничего**.
- О моделях: у Сергея стоял Opus 4.7, переключить было «в падлу». Работает и на «48», видимо Opus 4.8. Модель не критична, можно пользоваться даже Sonnet; базовая инфраструктура рассчитана «хоть и под хаику». - Смежные расходы: Higgsfield — двухлетняя безлимитная подписка по спецпредложению [27:55–28:05]; Railway для cron [139:04–139:12]; настройка под ключ от €1000 [93:06–93:11].

## 11. Выводы

### Надёжно и полезно
1. **Схема доступа к Marketing API** (приложение разработчика, System User с ролью Admin, токен с рекламными правами) — стандартный путь, локальный репо его подтверждает. Практически ценные детали из эфира:
   - сначала подключить приложение к активам БМ, потом генерировать токен, иначе будет «No permission»;
   - токен показывают один раз;
   - приложение надо опубликовать, иначе упрётесь в ограничения;
   - App ID, App Secret и токен держать под рукой.
2. **Сначала контекст, потом запуск.** Онбординг с ДНК клиента, сегментами, офферами, KPI, бюджетом с указанием периода, ID активов, допустимыми CPA и ROAS. Медиаплан утверждает человек.
3. **Разумные тактики:**
   - для нового пикселя оптимизация на ViewContent и InitiateCheckout вместо покупки;
   - бенчмарки по всей воронке метрик;
   - первым шагом разбор истории кабинета (только чтение, безопасно);
   - тест оффера малым бюджетом;
   - под каждый сегмент свой лендинг и своя пачка креативов.
4. **Честные признания самого Сергея:**
   - базовый агент не автономен;
   - ИИ-креативы часто слабые, простая статика бывает лучше;
   - дефолты агента (Advantage) приходится править;
   - самый болезненный этап — доступы, и прокликать их Claude пока не может.

### Сомнительно или хайп
1. **«MCP кастрирован, а наш путь — официальное приложение, не сторонний софт».** Это путаница. Приложение и System User — способ получить токен, а агент из репо работает через сторонний MCP-сервер pipeboard-co/meta-ads-mcp. Что умеет официальный коннектор Meta, в эфире не проверяли. Ведущий сам себе противоречит [07:56] и [77:36], а в инструкции ведущих есть шаг «установка MCP-коннектора» [44:35–44:41]. Проверять по документации Meta.
2. **«Блокировок не будет».** API-доступ от модерации не защищает: блокируют за содержание объявлений, платежи, подозрительную активность. Пример из самого демо: тексты вроде «первые 200 долларов живьём», «долларовый доход», «пособие режут» стоит проверить на правила Meta об обещаниях дохода и о намёках на финансовое положение аудитории.
3. **«Меня устраивает $15 вместо $150 — делай».** Агент не может заставить аукцион. При нереальном CPA он либо сожжёт бюджет, либо не наберёт данных.
4. **Нет доказательств эффективности.** Ни одного CPL или ROAS «до и после агента». Креативы на показанных дашбордах делал не агент; «20/17 проектов» и «результаты другие» остаются на слово.
5. **«Справится человек, который ничего не понимает»** — с оговоркой. Сергей сам признаёт, что нетехническому человеку подключение даётся тяжело; у ведущих ушёл почти час при готовых кабинетах.
6. **Коммерческий контекст.** Эфир продаёт обучение ведущего, настройку под ключ от €1000, расширенную версию и услуги агентства. Отсюда и превосходные степени: «гений», «западные курсы не стоят».
7. **Покупка БМ или аккаунта, VPN** как решение противоречат условиям Meta: покупать и продавать аккаунты там запрещено. Это риск бана и потери денег, особенно на клиентских кабинетах.

### Риски
1. **Токен.** Бессрочный, админский, «со всеми правами», на кабинеты и страницы; лежит открытым текстом в локальном конфиге (по репо — `.mcp.json`). Фраза «никуда не утекают» неточна: Claude Code запускается локально, но вся переписка, включая вставленные ключи, уходит на обработку модели в Anthropic и сохраняется в локальных логах сессий. Утечка токена — это полный контроль над рекламой и страницами клиента. Что делать:
   - минимальные права (для аналитики хватит ads_read);
   - отдельный System User на клиента;
   - ротация токенов;
   - вписывать ключи в файл самому, а не через чат;
   - проверить, что `.mcp.json` в .gitignore;
   - не выкладывать папку агента в публичный репо.
2. **Деньги.** С правом ads_management агент может создавать и включать кампании, менять бюджеты. В эфире не было ни лимита расходов аккаунта, ни запуска на паузе по умолчанию, ни подтверждения перед тратой. В репо такие правила есть (safety_rules.md), но это инструкция в промпте, а не жёсткий запрет: модель может её нарушить. Жёсткие страховки ставят на стороне Meta: лимит расходов аккаунта, небольшие дневные бюджеты, отдельная карта.
3. **Автономная версия.** Каждые 2–3 часа она сама режет бюджеты, выключает, дублирует и масштабирует — это действия с деньгами без человека. Задержка атрибуции или ошибка в данных дадут неверные решения. Нужны журнал, пороги, уведомления и режим «сначала покажи план».
4. **Политика Meta.** Массовые автоматические правки на новом аккаунте, покупные БМ, объявления с обещанием дохода, специальные категории (кредиты, работа, жильё и т. п.). В эфире ничего из этого не разбирали.
5. **Данные клиентов.** ДНК, данные кабинета и пикселя проходят через LLM. Для клиентских проектов нужны согласие и NDA.
6. **Хрупкость.** Интерфейс Meta меняется, и инструкции устаревают. Публичный репо могут закрыть (ведущий на этом настаивал), так что стоит держать свою копию и проверить лицензию.
7. **Уровни доступа приложения.** В эфире неопубликованное приложение «ограничено». В репо сказано: «Permission denied, если App в Development», публикация 1–3 дня. Агентству, которое ведёт чужие кабинеты, может понадобиться расширенный доступ и проверка приложения в Meta (App Review). Это надо уточнить по документации.

### Что брать в брифинг, а что нет
- **Брать:** схему доступа (с минимальными правами), онбординг-бриф, медиаплан на утверждение, два сценария для пикселя, бенчмарки, разбор истории кабинета, узкие лендинги под сегменты, совет «скриншот в чат».
- **Не брать:** «full access, все права, Never и ключи в чат», покупку БМ и VPN, автономные действия без жёстких лимитов, веру в CPA «по приказу».
