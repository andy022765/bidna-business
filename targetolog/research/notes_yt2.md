## 1. Кто говорит, о чём, для кого

Это запись Zoom-практикума онлайн-курса «AI-маркетолог». Ведёт модератор курса, его имя не звучит. Основной спикер — Сергей («Сергей», «Серёжа» на [01:24], [17:28], [93:08]), автор агента-таргетолога на Claude Code. В самом транскрипте не названы ни фамилия, ни компания, ни ссылка на GitHub или Notion. Что это Сергей Харьковщенко и репозиторий skipaoff/ai-target-agent, известно только из первой сессии (yt_RRTG0mcam8U, [13:40]) и из воркбука **[вне видео]**. В разговоре упоминается Влад, который раньше рассказывал «про сложности Фейсбука» [34:09–34:13]. Судя по воркбуку (там ссылка на yasikvlad/content-system), курс связан с Владом Яско **[вне видео]**.

О себе Сергей говорит так: у него продюсерский центр [62:24], «всю жизнь» он работает с холодным трафиком, воронками и автоворонками [68:22–68:27]. В пике у него было 25 сотрудников, сейчас «один и 27 других ИИ-сотрудников» [61:28–61:36].

Это **вторая часть практики**. Прошлая встреча закончилась выпуском токена System User. Эта начинается с момента, когда токен есть, кабинет настроен, оплата подключена, контент и информация о клиенте собраны [01:46–02:02]. Сергей показывает всё на реальном платящем проекте, «на который чуть подзабил» [02:40–02:46]. Судя по ссылкам в гривне и долларах [33:03–33:09], проект украинский. В программе: аудит кабинета, план перезапуска, создание кампании агентом, проверка в Ads Manager, включение. Вторая половина видео — вопросы и ответы.

Аудитория — ученики курса, в основном не таргетологи: предприниматели и маркетологи. По словам ведущих, большинство ещё не прошли этап с токеном, его успели сделать «два человека» [49:12], [93:25–93:28].

## 3. Техническая установка

**Главное:** само подключение в этом видео **не показывают**: приложение Meta, выпуск токена и установку агента делали в первой сессии, они описаны в воркбуке. Здесь есть только упоминания и один подробный разбор — выдача доступов.

**Что сказано в видео**
- **Инструмент — Claude Code.** Сначала Сергей собирал агента в Antigravity и VS Code, потом «перевёл просто на клодкод», чтобы всё было «в одном месте» [50:11–50:23], [51:03–51:09]. Базовая версия ставится локально, креативы и документы лежат в папке проекта [54:39–54:52].
- **Связка с Meta:** «подключили вот этот system user к нашему агенту… скинули все токены, создали приложение» [03:15–03:20]. Позже: «создали system user и приложение, получили все токены» [45:38–45:45]. Без токена Claude настроить рекламу не может [14:35–14:40]. Какой MCP-сервер, какие права у токена, какой срок жизни, нужна ли бизнес-верификация — **в видео не сказано**.
- **Выдача доступов System User [45:48–47:25]:**
  1. Business Manager → вкладка Users (там People, Partners, System users) → свой System User.
  2. Справа три точки → Assign assets (в субтитрах «SNSS»).
  3. Отметить рекламный аккаунт, страницу Facebook, Instagram и пиксель. Фраза «пикселя уже нету… [неразборчиво] есть» [47:15–47:18] вероятно значит, что пиксели теперь лежат в разделе Datasets.
  4. Выбрать **Full access**, «обязательно» [47:21–47:25].
  - Без доступа к пикселю агент не запустит кампанию с конверсиями на сайт и сам напишет, что доступа нет [46:29–46:47]. Доступы стоит проверить до онбординга или сразу после него [46:47–46:58].
  - Для клиентских проектов: сначала получить доступ к Business Manager клиента, потом открыть своему агенту доступ к его кабинету, пикселю и остальному [63:42–63:54]. Подключение нового проекта Сергей называет «самым геморройным» этапом [35:14–35:28].
- **Пиксель:** на новом проекте его «желательно провести вручную» [35:08–35:14]. После создания нужно самому пройти путь до заявки или покупки, чтобы события появились в Facebook [35:35–35:55]. Агент объяснит пошагово, как создать и назвать пиксель и куда вставить его на сайте [36:07–36:33]. Если подключён «браузерный MCP», агент сам откроет сайт и прогонит тестовое событие [36:33–36:54].
- **Инфраструктура продвинутой версии** (участникам её не выдают): cron на Railway [58:40–58:44], данные на Supabase, через GitHub и Railway [55:03–55:13], дашборды на Vercel [55:42], [56:04–56:14].

**[вне видео], для полноты.** Воркбук описывает создание приложения Meta (use case «Create & manage ads with Marketing API») и три ключа: App ID, App Secret и токен System User. System User получает роль Admin. Срок токена — **Never** (вариант «60 days» не брать). Права: ads_management, ads_read, business_management, плюс совет «отмечай сразу всё», чтобы агенту хватило прав на креативы и страницы. Токен показывается один раз. Все три значения отправляют в чат Claude Code. В репо, в файле `.mcp.json.example`, указан MCP-сервер `meta-ads` (`uv run … meta-ads-mcp`) с переменными META_APP_ID, META_APP_SECRET и META_ACCESS_TOKEN. Бизнес-верификацию не упоминают ни видео, ни воркбук (проверено поиском по тексту).

## 5. Как работает агент

**Онбординг.** Агенту передают ссылки, пиксель, страницы Facebook и Instagram, KPI, «все максимальные детали» [03:28–03:38]. Обязательно назвать, сколько «адекватно платить Фейсбуку» за продажу или регистрацию [11:17–11:28]. Если данных не хватает, агент спросит сам, например ID страницы или есть ли пиксель [47:41–48:06]. Каждый проект заводится под своим названием, потом к нему обращаются по названию проекта или кабинета [51:39–51:45], [54:00–54:06].

**Бриф и медиаплан.** Планировщик задаёт вопросы: сколько аудиторий, какое гео, добавлять ли интересы, какой возраст [07:55–08:07]. Если не знаете ответов, попросите медиаплан «на базе онбординга»: гео, возраст, интересы, число аудиторий [08:16–08:43]. План можно править. Например, агент советует 10 креативов, а у вас их два, тогда «сначала запускаем два» [06:17–06:28].

**Структура кампании**
- Бюджет на уровне кампании (CBO, «budget optimization») или на уровне адсета — это рекомендует агент [06:43–06:52]. Что выбрано в демо, не проговорили.
- Адсетов «три и не более». Довод — фаза обучения: каждому адсету нужно набрать определённое число конверсий [09:56–10:09].
- Адсеты делятся по гео (локация 1, локация 2), убыточные страны исключаются [10:09–10:26].
- Цель — конверсия «покупка» на лендинге. Агент также показывает атрибуцию и ставку [10:48–11:03].
- **Advantage агент предлагает отключить**, «иначе сольёт» контроль. Речь о возрасте и аудитории [11:03–11:10].
- В демо: 1 кампания, 2 адсета, 4 объявления на основе креативов-winners [27:46–27:49], [28:12–28:21], [32:13–32:17]. Новая кампания называется «Super Hair Winners», рядом старая «Site Purchase» [31:55–32:05].

**Таргетинг.** Широкий, без детального таргетинга [11:10–11:15], [32:39–32:44]. В демо агент сам собрал в одну локацию «рабочие» страны, где раньше были регистрации и продажи [32:30–32:39]. Страны он отбирает по ROAS [24:49–24:56].

**Бюджеты.** Стартовых сумм и правил масштабирования в видео нет. Пример «$50 в день» Сергей сам называет утрированным [22:44–22:50]. Цель по цене нужна реалистичная: если поставить «$1 в любом бизнесе», будет «максимально неэффективно» [11:42–12:05]. Если цену не задать, агент предложит свою, причём «по хаям», вероятно с запасом вверх: при допустимых $5 может предложить и $10 [11:28–11:39].

**Креативы**
- Основа — winners, то есть креативы, которые «нормально перфомят» в связках [24:22–24:31].
- Новые креативы можно передать тремя способами. Папкой Google Drive по ссылке [28:31–28:44]. Через All Tools → Creative Studio, после чего сказать агенту «я загрузил новые креативы» [37:37–38:01]. Или попросить запустить последний пост из Instagram [38:59–39:30]; пробные Reels агент не видит [39:33–39:46].

- Генерация: Higgsfield или HeyGen (аватары, UGC) [42:57–43:18]. Бесплатные варианты от самой Meta появляются, когда загружаешь в кабинет новую картинку [80:53–85:26]. Видео Meta генерирует «очень плохие» [84:59–85:04].

**Тексты.** Агент пишет основной текст и заголовки и согласует их с человеком; подробно это показывали в прошлый раз [48:31–48:45]. В демо он сам подставил текст, CTA и правильную ссылку: у проекта есть ссылки в гривне и в долларах, и он выбрал долларовую [32:56–33:17]. Дальше в субтитрах «по моему алгоритму добавил… для этой компании» [33:17–33:25]; что именно добавлено, не разобрать.

**Запуск.** Агент спрашивает, настраивать ли кампанию. После ответа «да» он всё создаёт, и в базовой версии **по умолчанию ставит на паузу**, «чтобы вы не сливали бюджет» [26:19–26:41]. Включает по команде: сначала кампанию, потом адсеты и объявления, после этого перепроверяет [34:28–34:40]. Своему агенту Сергей подтверждений уже не пишет: тот «меня знает», сам себя проверяет и сразу включает [33:50–34:07].

**Оптимизация**
- У Сергея агент раз в день сам анализирует, оптимизирует, перезапускает кампании, выключает креативы и добавляет новые кампании [23:15–23:33].

- **В базовой версии автоматики нет**: оптимизацию запускают командой вручную, для автономной работы нужен сервер [59:14–59:34].
- **Порогов для решений в видео не называют**: ни CPA, ни CTR, ни частоты, ни сколько ждать. Единственный ориентир — «средний CTR — 3% максимум» [81:36–81:42]. **[вне видео]:** у /ads-optimizer в воркбуке заявлены Health Score (от −100 до +100), поиск «ad-eaters» и учёт истории действий за 3 дня.

**Отчёты.** Каждый день в чат с клиентом или партнёрами приходят продажи за день против KPI (больше 15 продаж в день) [59:56–60:28]. Раньше это вручную делал отдельный сотрудник [61:08–61:17]. По запросу агент сводит все кабинеты в таблицу с активными кампаниями и расходами [51:57–53:54].

## 6. Безопасность и ограничения

- **Пауза по умолчанию** в базовой версии. Первые несколько запусков надо проверять руками: креатив, ссылку, страницу [26:25–27:07].

- **Самопроверка по онбордингу** до включения и после [27:12–27:32], [34:34–34:40].
- **Доступы:** агент получает **Full access** к кабинету, странице, IG и пикселю [47:21–47:25]. Это широкие права, см. раздел 12.
- **Один токен на двоих** Сергей разрешает («можно») [73:46–73:53]. Участник на это: «мне не стрёмно дать ключ» [76:38–76:45].
- **KPI должен быть реалистичным**, иначе кампания будет «максимально неэффективной» [11:42–12:05].
- **Модерация и баны:** банов «ни разу» не было, но все ниши «белые». Один отказ модерации был из-за слова «заработок», его сняли апелляцией [77:54–78:10].

- Про лимиты Marketing API, лимит расходов аккаунта, журнал действий и откат изменений **в видео ничего не сказано**.

## 12. Выводы

**Надёжно и полезно**
- Выдача доступов System User (Assign assets → Full access к кабинету, странице, IG, пикселю). Именно на этом шаге застревают ученики, и в видео он разобран хорошо [45:48–47:25].
- Безопасный цикл: план → «да» → создание на паузе → проверка человеком или агентом → включение → перепроверка [26:19–27:32], [33:42–34:40]. Его стоит сделать обязательным всегда, а не только «на первое время».
- Креативы передавать через Google Drive или Creative Studio, файлы подписывать под ленту и сторис, карусель заказывать явно [28:26–31:34].
- Разумные настройки: не больше 3 адсетов из-за фазы обучения, широкий таргет, разбивка по гео с исключением убыточных стран, реалистичный CPA. Это совпадает с обычной практикой Meta: классическая рекомендация — около 50 оптимизационных событий на адсет за 7 дней.
- Пиксель на новом проекте подключать руками и прогонять тестовое событие [35:08–35:55].

**Сомнительно или хайп**
- **Автономность показана на продвинутой серверной версии, а участники её не получают**: cron на Railway, Supabase, общий контекст [58:40–59:34], [73:46–74:42]. В базовой версии оптимизацию запускают вручную [59:19–59:24]. Слова модератора, что у участников «точно такой же скил», что и у Сергея [60:47–60:53], этому противоречат.
- Сергей говорит про «штук 50» скилов [17:55], а в публичном репо их 12 **[вне видео]**.
- Главного в видео нет: правил оптимизации (пороги CPA, CTR, частоты, сроки, шаг масштабирования). Решения, по словам Сергея, всё равно принимают его «мозги» [64:49–64:56].
- Показанный проект якобы три недели работал сам, но при ручном запросе агент сразу нашёл в нём «слив» по гео [09:01–09:24], а Сергей признал, что проект «подзабыт» [02:40–02:46]. Ежедневная автоматика этот слив не остановила.
- CTR 15–17% на креативах от Meta получен в единичном эксперименте [81:20–81:42]. «Банов не было» сказано про белые ниши [77:56–78:01]. «Бесконечный контекст» в Antigravity технически сомнителен: размер контекста задаёт модель, а среда разработки может разве что сжимать историю [50:53–50:58]. История «25 сотрудников → 1 + 27 ИИ» — это подача для продаж.
- Часть видео уходит на продажу услуг («можешь к нам обратиться» [43:45–43:48]) и офтоп: тренд-платформа, видеоредактор, липсинк.

**Риски**
- **Токен.** System User с Full access и, по воркбуку, сроком Never **[вне видео]** — это бессрочный ключ ко всем привязанным кабинетам с подключённой оплатой. Хранится он открытым текстом в локальном конфиге (`.mcp.json`, переменные окружения). В продвинутой версии данные идут через GitHub, так что секрет можно случайно закоммитить. Совет «один токен на двоих» [73:46–73:53] ломает аудит: не видно, кто что сделал. С БМ клиентов риск ещё выше.
- **Деньги.** Агент Сергея включает кампании без подтверждения [33:50–34:07] и при бюджетах $1–2 тыс. в день меняет их каждые 3 часа [58:26–59:10]. Нужны предохранители: лимит расходов аккаунта в Meta (Account spending limit), потолок дневного бюджета на кампанию, подтверждение человеком при повышении бюджета и при включении, журнал действий, создание новых кампаний на паузе по умолчанию.
- **Политика Meta.** Вопрос о маркировке ИИ-контента остался без ответа [80:27–80:44]; действующие правила надо проверить самостоятельно. Автоматизация через браузер, как у Александра (Claude заходит в Facebook через Playwright, в субтитрах «Play White» [14:49–14:58]), вероятно, нарушает запрет Meta на автоматизированный доступ без разрешения. Это риск проверок и блокировок аккаунта; формулировку в условиях Meta стоит уточнить. Официальный путь, как у Сергея, — Marketing API через своё приложение и System User. Формулировки вроде «заработок» модерация отклоняет [78:04–78:10].
- **Путаница кабинетов.** Все проекты в одной сессии [51:30–51:34]. Перед любой записью в кабинет стоит требовать от агента подтвердить ID кабинета.
- **Данные.** Тестовые события и покупки через браузерный MCP [36:33–36:54] могут засорить статистику пикселя.

**Минимум для нашей установки (по материалам видео)**
1. Assign assets с Full access: кабинет, страница, IG, пиксель (датасет). Оплата привязана, тестовое событие пикселя пройдено.
2. Файл онбординга: ссылки, ID, реалистичный CPA, бюджет вместе с периодом.
3. Любой запуск — только через паузу и проверку: креатив, ссылка и валюта, страница, событие, гео. Самопроверка агента дополняет ручную, но не заменяет её.
4. Креативы — в папку на Drive с понятными именами: лента или сторис, нумерация для карусели.
5. В базовой версии запускать оптимизацию вручную по расписанию. Автоматику на сервере включать только после того, как пороги решений записаны явно и настроены лимиты расходов.
