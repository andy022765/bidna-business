# Реферальные ссылки партнёров. Оценка

Решение Андрея 25.09.2026: партнёру **20% с оплат клиента в течение первого года**.
Формат ссылок согласован с полосой ПИСЬМА (`Pivot/spisok/partnery/SSYLKI-FORMAT.md`).

## Как это будет работать

1. Партнёр получает `businessinteldna.com/p/<имя>`. Имя — только латиница, цифры,
   дефис и подчёркивание: этой же строкой метится оплата в Stripe, других символов
   он в `client_reference_id` не принимает.
2. `/p/<имя>` запоминает партнёра в браузере и уводит на существующую страницу —
   `/visibility/ru/#forma` или `/vera/ru/`. **Новой страницы не делаем** (решение ШТАБа
   25.09): у нас уже есть бесплатная проверка видимости, она и есть находка.
3. Метка едет дальше: в форму, в заявку, в письмо, и в кассу —
   `<ссылка Stripe>?client_reference_id=<имя партнёра>`.
   Отдельной кассы на партнёра НЕ заводим: правило «один продукт — одна касса»,
   ревизия на лишнюю кассу ругается и будет права.
4. **Ручная метка — основной путь, а не исключение.** Бухгалтер скорее напишет
   письмо-знакомство, чем даст ссылку. Значит партнёра можно поставить клиенту руками
   в любой момент, в том числе после оплаты.
5. Флаг «аттест-клиент CPA — без вознаграждения», ставится руками. Кодекс AICPA 1.520
   запрещает CPA брать вознаграждение по таким клиентам, и это не наша вольная трактовка.
6. Раз в месяц партнёру — кто пришёл, кто оплатил, сколько начислено.

## ЧТО НУЖНО ОТ АНДРЕЯ — ПРАВА STRIPE, ТОЧНЫМ СПИСКОМ

Путь: **Stripe Dashboard → Developers → API keys → ключ `rk_live_…gCNc` → Edit key →
Permissions**. Всё ниже — **только Read**, ни одного Write не прошу.

| Ресурс | Уровень | Зачем именно он |
|---|---|---|
| **Checkout Sessions** | Read | `client_reference_id` живёт ТОЛЬКО здесь. Без него неизвестно, от какого партнёра клиент. Это главное право; сейчас API отвечает `more_permissions_required`. |
| **Customers** | Read | Связать сессию оплаты с покупателем, чтобы потом найти его месячные счета. |
| **Invoices** | Read | Абонентка $199/$399 списывается счетами. Двадцать процентов за год — это в основном они, а не первый платёж. |
| **Subscriptions** | Read | Понять, что подписка жива, и когда кончится первый год. |
| **Charges** | Read | Сколько денег реально пришло и сколько вернули: `amount_refunded` лежит на платеже. Без него начисление считается с сумм, которых у нас нет. |

Пять прав, все на чтение. Ключ уже умеет `Payment Links — Write` — этого хватает,
чтобы метить кассы, и больше писать никуда не надо.

## ПОЧЕМУ НЕ ВЕБХУК

Вебхук выглядит современнее, но для месячного начисления он хуже по четырём причинам:

1. **Это больше прав, а не меньше.** Завести приёмник нужно право
   **Webhook Endpoints — Write**. Просить Write вместо Read — движение не в ту сторону.
2. **Вебхук не видит прошлого.** Он начинает с момента создания. Оплаты, которые
   случатся до постройки, останутся невидимыми навсегда, и первый же отчёт партнёру
   окажется неполным.
3. **Потерянное событие теряется молча.** Stripe повторяет доставку до трёх суток
   и сдаётся. 23.09 у нас кончились кредиты Netlify и весь сайт лежал сутки — это ровно
   то окно, в котором событие пропало бы, а мы бы не узнали.
4. **Сверять всё равно нечем.** Даже с вебхуком, чтобы ответить «сколько партнёру
   за год», нужно читать счета. То есть права на чтение понадобятся вторым заходом.

Чтение по расписанию раз в сутки таких изъянов не имеет: оно видит и прошлое, и настоящее,
а пропущенный запуск догоняется следующим.
