## Что делает

1. **Визиты.** Раз в час `planirovshchik` читает календарь записей клиента (как Вера — служебным ключом) и метки Веры
   `otzyvy-vizit:<id события>` из её хранилища `golos-pisma` (только чтение; метку ставит патч `dlya-very/`).
   **Почта — только подтверждённая**: адрес, на который pismo.js реально отправил подтверждение записи
   (`pochta_podtverzhdena: true`). Адрес, названный при записи (строка «Почта:» в описании события), слышала
   модель и никто не подтверждал — по нему не шлём (`pochta_ne_podtverzhdena` в журнале). Два разных подтверждённых
   адреса на одну запись — не шлём (`pochta_neodnoznachna`). Записи Веры до патча попадают в журнал без почты.
   Метка из другого календаря — не наша. Два включённых паспорта с одним календарём не работают оба.
   Визиты не через Веру владелец вносит формой или CSV (`/vizity?t=…`, не больше `forma.v_sutki` = 200 за сутки).
   Ссылку формы в первый день пилота берём ручным запуском `{"chto":"ssylki","klient":"…"}` (дальше — в месячном отчёте).
2. **Просьба.** Через 2–3 часа после конца визита, только с 9:00 до 19:00 по времени бизнеса (вечерние — утром),
   письмо по образцу из плана (англ., для русской линии Веры — русское): одна кнопка на форму отзыва Google,
   адрес бизнеса, отписка, заголовки `List-Unsubscribe` + `List-Unsubscribe-Post`. Ответ посетителя — владельцу (Reply-To).
3. **Напоминание** — одно, через 3 дня, если не было клика. Больше писем нет.
4. **Не шлём**, только если: запись отменена или удалена, «no show»/«неявка» в названии, нет почты, отписан,
   этот адрес просили за последние 180 дней, опоздали больше 48 ч. Каждое такое решение — в журнале с причиной.
   Ручного «не слать этому» нет. Нет вопроса «довольны ли вы», скидок, выборочной рассылки.
5. **Слежение** по расписанию раз в 3 часа, но только с 8:00 до 21:00 по времени бизнеса (~5 запросов на клиента
   в сутки; ночной отзыв ловит утренний опрос — тревога владельцу ночью не приходит): Places API (New), только
   `rating` и `userRatingCount`, потолок 40 запросов в сутки на всех. Тексты из Google не запрашиваются и не хранятся.
   Храним только два числа последнего опроса (не дольше 30 дней); истории чисел нет.
6. **Тревога** владельцу по-русски: по опросу (числа говорят, что пришёл отзыв ≤3★) — «вставьте текст, пришлём ответ»;
   по вставленному тексту (1–3★ или 4★ с жалобой) — черновик Claude (Sonnet 5, без размышления) + кнопки
   «Скопировать и открыть отзыв · Опубликовал · Править · Не отвечать». Кнопки ведут на страницу, действие — POST.
7. **Отчёт** 1-го числа (с 9:00 по времени бизнеса) HTML-письмом: просьбы, напоминания, клики, исключения по причинам,
   отписки, рейтинг и число отзывов на день отчёта (живой запрос; сравнение — с прошлым отчётом в почте), разбор
   плохих отзывов, 2–3 соседа. Холостые «письма» в отчёте не считаются. Resend не ответил (таймаут) — отчёт не повторяем
   (мог уйти; ключ повтора Resend живёт сутки), в журнале `neizvestno`.
8. **Неявки** по понедельникам: больше 20% записей за неделю без письма (неявка/отмена/удаление) — письмо владельцу с копией нам.
   В знаменателе и визиты недели, ещё ждущие напоминания (иначе доля завышалась).
9. **Выключатель** в Blobs (по умолчанию выключено) + `vklyuchen` в паспорте + `rezhim: suhoy|boevoy`. **Здоровье** — `zdorovie`.
   Холостой режим: визит считается обработанным (настоящего письма по нему потом не будет), но в правило
   «не чаще раза в N дней» холостая просьба не пишется — человек получит просьбу после следующего визита.
10. **Дубли.** Замок «в работе» старше 20 ч не повторяем (ключ повтора Resend живёт сутки) — визит закрывается
   `neizvestno_ushla_li_prosba`. Черновик Claude по одному отзыву — один раз (замок), черновик со служебными тегами
   владельцу не отдаём.

1. `skripty/nastroit-odin-raz.sh sekrety` → дописать в `~/.bidna-otzyvy.env` ключи Resend, Places, Claude, `EV_BLOBS_TOKEN`.
2. `… sozdat` → `OTZYVY_SITE_ID` и `OTZYVY_BAZA_URL` в тот же файл → `… peremennye` (ставит и `OTZYVY_SUHOY=1`) → `… klyuch`.
3. Заполнить паспорт (`place_id`, закрытый календарь записей, соседи), `vklyuchen` не трогать.
4. `skripty/vylozhit.sh` → в выводе `zdorovie`. Через 2 часа — `puls.planirovshchik.v_norme: true` (расписание подхватилось при выкладке через CLI — это не проверено, PLAN-V1 п. 2).
5. Обкатка: паспорт `vklyuchen: true`, `rezhim: suhoy`, `skripty/vyklyuchatel.sh vkl`, ручной прогон:
   `curl -X POST -H "x-otzyvy-admin: $OTZYVY_KLYUCH_ADMINA" -d '{"chto":"planirovshchik","klient":"obkatka"}' $URL/.netlify/functions/zapusk`.
   Потом `rezhim: boevoy` и письма на наш адрес. У клиента включать — только по слову Андрея.

Грабли: CLI берёт привязку из корня проекта (там чужой сайт) — только `NETLIFY_SITE_ID` и `--site=<id>`; переменные подхватываются только выкладкой;
без `EV_BLOBS_TOKEN` Blobs из функции не поднимаются и метки Веры не читаются; `OTZYVY_SECRET` после первых писем не менять (сломаются ссылки отписки).

## Открыто после ревью 29.09 (решения Андрея или живая проверка)

- **Условия Google Maps Platform.** Храним два числа последнего опроса (≤ 30 дней), без них тревогу по опросу не
  поднять. Строгое чтение условий разрешает хранить только place_id. Варианты: принять риск или убрать тревогу по опросу
  и жить только на письмах Google менеджеру. Точную формулировку условий сверить до первого клиента.
- **Меньше просьб, чем визитов с почтой:** просим только тех, кому Вера отправила подтверждение (адрес зачитан по буквам
  и подтверждён). Долю покажет первый клиент.
- **Отскоки** в новом аккаунте Resend не обрабатываются (напоминание уйдёт и на несуществующий адрес).
- **Метки Веры** копятся без срока (в них подтверждённая почта) — чистка на стороне Веры отдельной правкой.
- Живьём не проверены: расписание при выкладке CLI, заголовки отписки у Resend, POST отписки через перенаправление Netlify.
