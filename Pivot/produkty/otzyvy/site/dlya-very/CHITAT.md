# Правка у Веры для Сборщика отзывов

Собрано 29.09.2026, переделано после ревью 29.09 вечером. **Живой код Веры не менялся.** Патч проверен на копии
во временной папке вне Drive.
Выкатывать только в окно выкатки по «да» Андрея (по плану — ср 07.10, вместе со Сборщиком в выключенном виде).

## Зачем

Сборщику нужно знать по каждой записи Веры: какое это событие календаря и на какой адрес ушло подтверждение.
Сейчас метка `zapis:<разговор>` в `golos-pisma` хранит только время словами (PLAN-V1 п. 1).

## Что меняет патч (`vera-otzyvy.patch`, три файла)

| Файл | Что |
|---|---|
| `golos/site/netlify-functions/kalendar-zapis.js` | После записи: в `zapis:<разговор>` добавлен `event_id`; новая метка `otzyvy-vizit:<id события>` — календарь, начало и конец визита, имя, язык линии. **Почты в ней нет**: адрес, названный при записи, слышала модель, и его никто не подтверждал (ревью 29.09). Ставится и без id разговора. Сбой метки запись не ломает. |
| `golos/site/netlify-functions/pismo.js` | После ушедшего подтверждения записи: в `otzyvy-vizit:<id>` дописывается адрес, на который оно реально ушло (`pochta_podtverzhdena: true`). Письмо не ушло — адрес не пишется. Метка записи живёт весь разговор: если второе письмо в нём ушло на **другой** адрес («пришлите и коллеге» или исправленный), метка получает `pochta_neodnoznachna: true`, первый адрес не затирается, и Сборщик по ней не пишет никому. Сбой метки письму не мешает. |
| `golos/proverka/test_otzyvy_metka.js` | Новая проверка, 17 пунктов. С патчем проходит, без патча падает; на прежней версии патча (29.09 днём) падает в 3 пунктах. |

Новых переменных у сайта Веры нет. Поведение для звонящего то же: ответы инструментов не изменились.

## Как проверить (ничего не трогает)

```
produkty/otzyvy/site/dlya-very/proverit-patch.sh
```
Копирует `Pivot/golos` (без node_modules и web) во временную папку, накладывает патч, гоняет все
`golos/proverka/test_*.js` до и после и новую проверку. 29.09: коды выхода всех 22 проверок Веры
совпали до и после (14 зелёных; 8 красных падают и без патча — им нужны свои аргументы или окружение),
новая проверка 17 из 17, без патча падает. Перепроверено после переделки 29.09 вечером — то же.

## Как наложить (в окно выкатки, по «да» Андрея)

```
cd "Pivot"
patch -p1 --dry-run < produkty/otzyvy/site/dlya-very/vera-otzyvy.patch   # должно пройти молча
patch -p1 < produkty/otzyvy/site/dlya-very/vera-otzyvy.patch
node golos/proverka/test_otzyvy_metka.js
node golos/proverka/test_kalendar_metka.js
node golos/proverka/test_pismo_zapis.js
node golos/proverka/test_pismo.js golos/site/netlify-functions/pismo.js
```
Если Веру правили после 29.09 и патч не ложится — не править руками наугад: снова собрать патч по
её свежему коду (две вставки описаны выше).

Выкладка — обычным путём сайта Веры (`dezhurny-r4p8w2`), точку отката записать до выкладки.

## Сразу после выкладки (PLAN-DLYA-ANDREYA п. 9)

1. Проверочная запись у Веры: встреча встала, подтверждение пришло.
2. В `golos-pisma` есть `otzyvy-vizit:<id события>` с `pochta_podtverzhdena: true` и тем адресом.
   Посмотреть: `NETLIFY_SITE_ID=4583b8b6-f9f4-4fae-b369-d107c8ac56a3 npx netlify-cli blobs:get golos-pisma "otzyvy-vizit:<id>"`.
3. За следующий час ни одного письма Сборщика (выключатель Сборщика выключен).

Откат: вернуть прошлую выкладку сайта Веры (около минуты) или `patch -p1 -R < …/vera-otzyvy.patch` и выложить.

## Открыто

- Метки `otzyvy-vizit:*` в `golos-pisma` копятся без срока — так же, как нынешние `zapis:*`. В них подтверждённая почта.
  Сборщик в чужое хранилище не пишет и не чистит (договорились только читать). Чистку старше 90 дней
  надо добавить на стороне Веры отдельной правкой — предлагаю вместе с её ближайшей выкладкой.
- Сборщик читает `golos-pisma` со своего сайта по `EV_BLOBS_TOKEN` (личный токен Netlify, видит все сайты
  аккаунта) и `site_id` Веры из паспорта клиента.
