### 5. Проверка stage до боя
**По умолчанию — локально, кредиты не тратятся:**
```
nohup python3 $SK/instrumenty/netlify_lok.py "$ST" 8793 > "$SCR/server.log" 2>&1 & echo $! > "$SCR/server.pid"
python3 shtab/sayty/reviziya.py --dom http://127.0.0.1:8793   # «ЧИСТО», код 0
python3 $SK/instrumenty/js_check.py "$ST"                     # 29.09: ок 149, с ошибкой 0

python3 shtab/sayty/mob_audit.py http://127.0.0.1:8793        # фоном, ~4 мин; итог и код — `$SK/etalony.md`
kill $(cat "$SCR/server.pid")
```
**Что умеет `netlify_lok.py`:**
- pretty URLs;
- `/vera` → 301 на `/vera/`;
- `_redirects` с `301` и `301!`;
- форма без `data-netlify`.

**Чего не умеет:** функций, `_headers`, правил со `*` и `200` (о них предупредит в `server.log`). sitemap, hreflang и canonical указывают на боевой домен, поэтому их проверяет `stage_ssylki.py`.

**Черновик нужен, только если менялись функции, edge-функции или `netlify.toml`, и только после «да» на окно.**
```
npx --yes netlify-cli deploy --site=$BOY --dir="$ST" --functions=netlify-functions --skip-functions-cache \
  --message "ЧЕРНОВИК <дата>" --json > "$SCR/deploy-draft.json"
node $SK/instrumenty/sverka_heshey.mjs <deploy_id черновика> "$ST" --strogo   # «ИТОГ: выкладка = stage», .eszip есть
```
- Черновик без входа в Netlify отдаёт **401**. `reviziya.py --dom <черновик>` на нём не работает, хотя комментарий в `reviziya.py:16` предлагает именно это. Показать черновик постороннему тоже нельзя.
- **Черновик никогда не публиковать через `restoreSiteDeploy`.** Он собран как deploy-preview, а четыре переменные есть только в production: `PARTNERY_KLYUCH`, `PROVERKA_NASH_KLYUCH`, `STRIPE_WEBHOOK_SECRET`, `ZDOROVIE_KEY`. Опубликованный черновик сломает вебхук Stripe, партнёрку и здоровье функций (29.09).

**Предпросмотр нужен, только если человек должен увидеть страницы глазами до боя, и только после «да» на окно.** Выкладывать только скриптом. Он закрывает индексацию (robots `Disallow`, `X-Robots-Tag noindex`, без `sitemap.xml`), не берёт неполный stage и не выложит на боевой:

Голую команду `deploy --prod --site=…` не набирай: перепутанный id выложит закрытую копию на живой в обход `deploy.sh`.
