## Пересказ по разделам

- Документация описывает поля серверного события Conversions API — общего эндпоинта для событий сайта, приложения и офлайн-источников.
- `event_name` (обязательное) — имя стандартного или кастомного события; вместе с `event_id` используется для дедупликации между событием из браузера/приложения (пиксель/SDK) и тем же событием с сервера. Совпадающие события, отправленные в пределах 48 часов друг от друга, считаются одним (учитывается первое); если браузерное/app-событие и серверное пришли почти одновременно — в пределах 5 минут, — Meta предпочитает браузерное/app-событие.
- `event_time` (обязательное) — unix-время в секундах по GMT, когда событие произошло на самом деле; может быть раньше момента отправки (для пакетной обработки), но не более чем на 7 дней: если хотя бы одно событие в запросе старше 7 дней, Meta возвращает ошибку и не обрабатывает вообще ни одного события из этого запроса.
- `user_data` (обязательное) и `custom_data` (необязательное) — данные о клиенте и дополнительные данные о самом событии; `event_source_url` (необязательное в общем случае, но обязательное для событий сайта) — URL страницы, где произошло событие, должен совпадать с верифицированным доменом.
- `event_id` (необязательное, но рекомендуемое для дедупликации) — любая уникальная строка рекламодателя; должна совпадать с `eventID` того же события, отправленного из браузера/приложения. Хороший вариант — номер заказа или транзакции; для событий без своего номера подходит случайное значение, если оно одинаково и в браузерном, и в серверном событии.
- `action_source` (обязательное) — где произошла конверсия; принимает значения: `email`, `website`, `app`, `phone_call` («конверсия по телефону»), `chat`, `physical_store`, `system_generated`, `business_messaging`, `other`. Отдельно оговорено: любое значение `action_source` даёт и измерение с построением кастомных аудиторий, и оптимизацию показа рекламы.
- `data_processing_options` (необязательное) — массив с принимаемым значением `LDU` (Limited Data Use); пустой массив явно означает, что ограничения LDU к событию не применяются. `data_processing_options_country` обязателен, если отправлен LDU: значения `1` (США) или `0` (пусть Meta определит геолокацию сама). `data_processing_options_state` обязателен в ряде случаев: значения `1000` (Калифорния) или `0`; если указана страна, обязательно указать и штат — иначе применяется геолокация по всему событию; поле также обязательно, если отправлен LDU и не передан IP-адрес.
- `app_data`/`extinfo` — обязательны для событий из мобильного приложения (расширенные данные об устройстве: версия ОС, модель, экран и т. п., каждое поле на фиксированной позиции массива). `original_event_data` — необязательное поле для привязки «отложенного» события к прошлому событию привлечения клиента (рекомендуется при задержке между событиями). `customer_segmentation` — необязательный enum для описания, новый клиент или существующий (для бизнеса, направления, продуктовой области или канала), включая отдельное значение для участников программы лояльности.

## Короткие цитаты для сверки (дословно)

> "If we find a match between events sent within 48 hours of each other, we only consider the first one."

> "If a server and browser/app event arrive at approximately the same time (that is, within 5 minutes of each other), we favor the browser/app event."

> "If any `event_time` in `data` is greater than 7 days in the past, we return an error for the entire request and process no events."

> "All action source values enable ad measurement and custom audience creation capabilities. All action sources enable ad optimization capabilities."

> "An empty array can be sent to explicitly specify that this event shouldn't be processed with the Limited Data Use restrictions."
