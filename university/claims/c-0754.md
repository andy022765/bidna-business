# Готовой связки Stripe → Meta Conversions API в справке Meta нет: CAPI подключается через Meta-enabled вариант (бесплатно, в один клик, только события пикселя с сайта), через партнёров (Shopify, WooCommerce, Wix, BigCommerce, теги, CRM — Stripe не назван) или прямой интеграцией (2–4 недели, единственный путь для офлайн- и app-событий)

## Context

Справка «Compare Conversions API setup options» (433493041367251), извлечено 27.09.2026. Отдельный список партнёров для веб-событий (260370078559247) прочитан и стоит в очереди: Stripe там тоже нет, есть Zapier, LeadsBridge, Make (Integromat), Square, GoDaddy. Сторонние коннекторы Stripe → Meta (Able CDP, LeadsBridge, Upstack Data, шаблон Zapier) — витрины, не проверены.

## Evidence walk-through

Таблица сравнения: Meta-enabled — бесплатно, в один клик, нужен только пиксель, источник — веб, события те же, что у пикселя, с автоматической дедупликацией; прямая интеграция — разработчик, 2–4 недели, источники — веб, app, офлайн, CRM, переписка; для офлайн- и app-событий «direct integration is the only available option». Партнёры названы группами, Stripe среди них нет. M: отсутствие упоминания — не доказательство отсутствия.

## Counter-evidence / edge cases

Stripe может появиться в каталоге партнёров Events Manager, которого в справке нет; проверить в интерфейсе. Meta-enabled CAPI повторяет только то, что увидел пиксель: если человек закрыл вкладку до страницы «спасибо», Purchase не будет ни там, ни там — поэтому серверный Purchase из вебхука нужен.

## Implication for project (подробнее)

- Задача ГОЛОСУ: вебхук Stripe → Purchase в CAPI, с дедупликацией по id сессии (c-0746).
- Таргетолог сверяет Purchase в отчёте Meta с оплатами в Stripe.
