# Итог звонка и другие офлайн-события передаются в Meta только через Conversions API прямой интеграцией (Offline Conversions API закрыт в мае 2025): с action_source=phone_call и не позже 7 дней после события, иначе отклоняется весь запрос; для оптимизации Meta использует офлайн-конверсии только в цели Sales с местом «сайт и магазин»

## Context

Справка «About Conversions API» (2041148702652965), параметры серверного события (Meta for Developers), справка «Compare Conversions API setup options» (433493041367251); извлечено 27.09.2026. Документ «Sending Offline Events Using the Conversions API» прочитан и стоит в очереди: для магазинных событий action_source=physical_store и загрузка в течение 62 дней, дедупликация офлайн-событий — по order_id или по данным клиента в окне 7 дней.

## Evidence walk-through

Справка: CAPI принимает события сайта, магазина, почты, чатов, телефона, приложения и офлайна; Offline Conversions API «will be discontinued in may 2025»; офлайн-конверсии идут в оптимизацию только в цели Sales с местом «сайт и магазин». Параметры: action_source принимает phone_call; событие старше 7 дней приводит к ошибке всего запроса. Справка о подключении: для офлайн- и app-событий подходит только прямая интеграция. Четыре согласованных документа — H.

## Counter-evidence / edge cases

Не проверено, поддерживает ли цель Sales с «сайт и магазин» событие phone_call как «магазин». Справка о Tracking в рекламе со звонком допускает CRM-события как отслеживание — эффект на оптимизацию не описан. Бриф-bidna §9 («CAPI принимает офлайн-события по телефонным звонкам из CRM») — подтверждается.

## Implication for project (подробнее)

- Порядок для ГОЛОСА: сначала пиксель и веб-события, потом серверное событие итога звонка.
- В журнале звонков Веры хранить email или телефон звонящего (с его согласия) — иначе офлайн-событию не с чем совпасть.
